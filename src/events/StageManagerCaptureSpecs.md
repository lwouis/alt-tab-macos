# Stage Manager capture protection

The General setting is off by default. On macOS 26 and later, it is active only while `com.apple.WindowManager` reports `GloballyEnabled`. Older macOS versions keep the private `.fullSize` capture path.

Protected requests only capture the focused window of the frontmost application. Focus-triggered captures wait 250 ms for the stage transition. Other windows retain their last verified thumbnail, or use the existing app-icon placeholder until visited. Ordinary captures also record whether their geometry and pixels were verified. Enabling protection keeps verified thumbnails and current-session full-resolution frames; only unverified images are discarded. This does not extend the ordinary cache or switcher-session lifetime.

Fresh Core Graphics bounds are checked off-main before creating the capture configuration and after the callback: reject missing, non-finite or non-positive geometry, or either dimension below 90% of the corresponding normal Accessibility size. The AX size is obtained off-main through `AXCallScheduler` before capture. The comparison uses logical window sizes, independent of display resolution; exactly 90% is accepted. Temporary transforms retain the last verified preview until a normal capture succeeds. `Window.size` is refreshed by WindowServer and can itself be scaled; an unavailable AX size leaves protected caches unchanged. Ordinary captures still display when verification is unavailable, but cannot later be inherited as trusted. ScreenCaptureKit output dimensions alone cannot detect a sidebar transform because it rescales to a configured canvas. Reject images smaller than 16 pixels on either axis or with fewer than 5% visible samples in a 16-by-16 alpha grid (alpha greater than 16).

Before publication on main, require the same mode generation, tracked Window object, and owner PID; protected publication also requires the same focus generation and focused window. Full-resolution frames also require the original switcher session. A mode toggle invalidates queued results, including an observed off/on cycle. System state is read on demand, without a timer or preference writes. Failed geometry/pixel validation gets at most three 250-ms thumbnail retries while the same window remains focused. Partial-frame retry exhaustion cannot replace a protected thumbnail with a known partial frame.

The pure geometry, pixel threshold, and mode-generation contracts are covered by `StageManagerCapturePolicyTests`. Native E2E must cover ordinary-to-protected inheritance, unknown geometry, unverified-frame rejection, and recovery. Real Stage Manager animations remain a separate hardware acceptance check.

- Background application tab/representative repairs must not invalidate a foreground capture. Actual foreground application changes and foreground window changes still advance the focus generation.
- Thumbnail acceptance computes partial-frame status once and commits pixels with their trust status. Ordinary partial frames accepted after retry exhaustion remain untrusted; protected partial frames retain the previous thumbnail.
